1. ENVIRONMENT SETUP & IMPORTS
================================================================================
File: train_kaggle.py | Lines: 1 – 108

What it does:
  Sets the PYTORCH_CUDA_ALLOC_CONF environment variable BEFORE torch is
  imported (this is critical — it must come first). Then imports all standard
  libraries: OpenCV, NumPy, Pandas, PIL, PyTorch and its sub-modules
  (nn, transforms, DataLoader, etc.).

  Optional libraries are imported with try/except blocks so the script still
  runs even if they are missing:
    - albumentations  → richer augmentation pipeline
    - sklearn         → AUC metric + Platt calibration
    - torch._dynamo   → torch.compile support

  ImageNet mean and std constants are defined here for normalisation.

Why it matters:
  The CUDA memory config prevents OOM fragmentation on Kaggle GPUs.
  The fallback imports make the code portable across environments.

3. CUSTOM AUGMENTATION CLASSES
================================================================================
File: train_kaggle.py | Lines: 110 – 251

These are domain-specific augmentations written as Albumentations
ImageOnlyTransform subclasses. They simulate real-world visual noise
specific to industrial rim inspection images.

  RadialBlur (Lines 113 – 130)
    Simulates motion blur caused by a spinning rim during imaging.
    Applies a diagonal convolution kernel of random size.

  SpecularHighlight (Lines 133 – 154)
    Adds a random elliptical bright spot to simulate reflections from
    metallic rim surfaces under directional lighting.

  ScratchSimulation (Lines 157 – 179)
    Draws random thin lines at random angles to simulate surface scratches.
    Uses cv2.line with near-white colours.

  SectorMask (Lines 182 – 202)
    Blacks out (fills with mean colour) a random angular sector of the image,
    simulating occlusion or partial capture of the rim.

  RimSpecificAug (Lines 205 – 250)
    Picks one of three modes randomly:
      "vignette" : darkens image edges toward the rim border
      "ring"     : adds a faint circular ring artefact
      "fixture"  : adds a thick bar on one side (mounting fixture shadow)

7a. ATTENTION MODULES
================================================================================
File: train_kaggle.py | Lines: 582 – 624

  AttentionPool2d (Lines: 582 – 592)
    Replaces global average pooling at the end of each backbone.
    A 1×1 convolution scores each spatial position. Softmax normalises
    scores across H×W. Output is a weighted sum — the model learns to
    focus on the most discriminative spatial regions (e.g., crack location
    on the rim).

  CBAM — Convolutional Block Attention Module (Lines: 595 – 615)
    Applied to each backbone's feature map BEFORE the attention pooling.
    Two sequential attention gates:
      Channel attention : shared 2-layer MLP on average-pooled and
                          max-pooled channel vectors — rescales channels
      Spatial attention : 7×7 conv on stacked mean/max maps — rescales
                          pixels
    Together these suppress background noise and amplify defect features.

  _get_out_channels() (Lines: 618 – 624)
    Helper to infer the output channel count of a backbone by running
    a dummy tensor through it. Used during model construction.

Notebook cell suggestion: "Cell 7a — Attention Modules"


================================================================================
7b. ENSEMBLE MODEL V6
================================================================================
File: train_kaggle.py | Lines: 627 – 722

  EnsembleModelV6 (Lines: 627 – 716)
    The main model. Combines three pretrained backbones in parallel:

      EfficientNet-B4  (Lines: 634 – 644)
        Split into b4_stem (first 6 feature blocks) and b4_last (rest).
        This split enables phase-wise unfreezing.

      RegNetY-8GF  (Lines: 646 – 656)
        A stronger alternative to ResNet-50. Split into rn_stem
        (stem + first 3 trunk stages) and rn_last (final stage).

      ConvNeXt-Small  (Lines: 658 – 668)
        Modern convolutional backbone. Split into cx_stem and cx_last.

    Each backbone:
      → CBAM → AttentionPool2d → Linear(320) + GELU + Dropout

    Fusion (Lines: 677 – 714):
      Backbone outputs are stacked as tokens and passed through a
      Multi-Head Cross-Attention layer (8 heads, embed_dim=320).
      This lets the 3 backbones "vote" and refine each other's features.
      The attended tokens are concatenated (960-dim) and gated by a
      learned sigmoid gate (fusion_gate).

    Classification head (Lines: 685 – 690):
      960 → 512 → 256 → 128 (GELU + Dropout at each step)
      Two output heads:
        binary_head   : predicts defect probability (used at inference)
        severity_head : auxiliary regression on defect severity
                        (regularises training, ignored at inference)

  build_model() (Lines: 719 – 722)
    Convenience function — instantiates EnsembleModelV6 with args.

================================================================================
8. LOSS FUNCTIONS
================================================================================
File: train_kaggle.py | Lines: 724 – 779

  FocalLossWithLogits (Lines: 727 – 741)
    Standard Focal Loss for binary classification. Reduces the weight of
    easy negative examples so the model focuses on hard positives (rare
    defects). gamma=2.0 is a standard choice. Supports label smoothing
    and class-weighted pos_weight.

  AsymmetricLoss (Lines: 744 – 762)
    ASL uses different focusing exponents for positive (gamma_pos=1) and
    negative (gamma_neg=4) samples. It clips easy negatives more
    aggressively than Focal Loss — better for class-imbalanced datasets.

  CombinedLoss (Lines: 765 – 779)
    Weighted combination:
      total = 0.6 * FocalLoss + 0.4 * ASL + 0.25 * MSE(severity)
    The severity MSE acts as a soft regulariser that shares gradient
    with the binary head.

Notebook cell suggestion: "Cell 8 — Loss Functions"


================================================================================
9. EMA (EXPONENTIAL MOVING AVERAGE)
================================================================================
File: train_kaggle.py | Lines: 781 – 801

  ModelEMA (Lines: 784 – 801)
    Maintains a shadow copy of the model whose weights are a running
    average of all past model states. The shadow model is used for
    validation and saved as the final checkpoint.

    Warmup decay (Lines: 796 – 797):
      d = min(decay, (1 + step) / (10 + step))
      This ramps the EMA from a fast-moving average at the start of
      training to the full 0.9998 decay after ~100 steps.

    Why use EMA?
      EMA models generalize better than the last checkpoint because
      they average out gradient noise. Standard practice in competitions.

10. MIXUP / CUTMIX DATA AUGMENTATION
================================================================================
File: train_kaggle.py | Lines: 803 – 828

  _mixup_cutmix(imgs, lbls, alpha=0.1) (Lines: 806 – 828)
    Applied inside the training loop to batches of images.
    With 40% probability (random.random() < 0.6 skips it):

      MixUp (50% chance):
        Blends two images pixel-wise: out = lam*img_A + (1-lam)*img_B
        Labels are blended the same way (soft targets).

      CutMix (50% chance):
        Cuts a random rectangle from image B and pastes it into image A.
        Label ratio reflects the proportion of pixels from each image.

    Both techniques prevent over-confident predictions and improve
    generalisation on small datasets.

11. TEST-TIME AUGMENTATION (TTA)
================================================================================
File: train_kaggle.py | Lines: 830 – 858

  _tta_predict(model, imgs, device, n_views=4) (Lines: 833 – 858)
    Runs multiple augmented views of the same batch through the model
    and averages the sigmoid probabilities.

    n_views=4  : 4 flips only (original, h-flip, v-flip, both flips)
                 Used during training validation (--tta-freq)
    n_views=16 : 4 flips × 4 rotations (0°, 90°, 180°, 270°)
                 Used for final evaluation only (--tta-views-final=16)

    TTA reduces prediction variance without retraining. Using 16 views
    at the very end extracts maximum performance from the trained model.

12. VALIDATION & THRESHOLD SWEEP
================================================================================
File: train_kaggle.py | Lines: 860 – 947

  _validate() (Lines: 863 – 915)
    Runs the model over the val/test loader in eval mode.
    Returns: accuracy, F1, precision, recall, AUC, raw probs, labels.
    Supports optional TTA. Optional profiling breaks down time spent
    in data loading, GPU forward pass, and CPU transfer.

  _sweep_threshold() (Lines: 918 – 947)
    Vectorised threshold search over [0.05, 0.96] with step 0.01.
    All thresholds are evaluated simultaneously on GPU using broadcasting —
    no Python loop needed (much faster than iterating thresholds).
    Returns the threshold with the highest F1 score.

    Why sweep thresholds?
      For imbalanced datasets the best decision boundary is rarely 0.5.
      The sweep finds the threshold that maximises F1 on the validation set.

14. PLATT SCALING CALIBRATION
================================================================================
File: train_kaggle.py | Lines: 965 – 984

  _calibrate_model() (Lines: 968 – 984)
    Fits a Logistic Regression on (raw_logit → true_label) pairs from
    the validation set. Saves the fitted calibrator to calibrator.pkl.
    At inference time, raw sigmoid outputs pass through this calibrator

      Neural networks are often overconfident. Calibrated probabilities
      give more reliable thresholding.

15. THREE-PHASE TRAINING SETUP
================================================================================
File: train_kaggle.py | Lines: 986 – 1056

  _setup_phase(model, phase, args, n_epochs) (Lines: 989 – 1056)
    Implements progressive unfreezing — a transfer learning strategy
    that avoids destroying pretrained features early in training.

    Phase 1 — Head warm-up (Lines: 1003 – 1015)
      ALL backbone weights frozen. Only the classification head,
      cross-attention, and fusion gate are trained.
      Optimizer: AdamW, lr=base_lr.
      Duration: --phase1-epochs (default 5)
      Purpose: initialise the head before touching the backbone.

    Phase 2 — Head + last blocks (Lines: 1017 – 1033)
      Backbone stems still frozen. Last blocks of each backbone unfrozen.
      Differential LR: head = base_lr, last blocks = base_lr × 0.1
      Optimizer: AdamW with per-group LRs.
      Duration: --phase2-epochs (default 8)
      Purpose: adapt the last feature extractor layers to the rim domain.

    Phase 3 — Full model (Lines: 1035 – 1048)
      All parameters trainable.
      Differential LR: backbone = base_lr × 0.02–0.04, head = base_lr
      Duration: --phase3-epochs (default 27)
      Purpose: end-to-end fine-tuning with heavy augmentation.

Notebook cell suggestion: "Cell 15 — Phase Setup"

        Falls back to fp32.

        AMP disabled, fp32.

17. MAIN TRAINING LOOP
================================================================================
File: train_kaggle.py | Lines: 1086 – 1302

  train() (Lines: 1089 – 1302)

  Seed & device setup (Lines: 1090 – 1103)
    Sets seeds for reproducibility (random, numpy, torch, CUDA).
    Enables cudnn.benchmark and TF32 on CUDA for throughput.

  Data preparation (Lines: 1107 – 1121)
    Loads samples, splits into train/val/test, builds DataLoaders.
    Saves val_split.csv for later analysis.

  Model & EMA setup (Lines: 1123 – 1141)
    Builds model, optionally applies channels-last memory layout,
    torch.compile, and wraps in ModelEMA.

  Loss setup (Lines: 1143 – 1151)
    Calculates pos_weight from class counts, initialises FocalLoss,
    ASL, and CombinedLoss.

  SWA setup (Lines: 1154 – 1162)
    Wraps model in AveragedModel for Stochastic Weight Averaging.
    SWA begins at --swa-start epoch and uses a cosine LR annealing.

  Resume logic (Lines: 1174 – 1186)
    If a checkpoint exists at --resume, loads weights, restores epoch
    counter and best_val_f1 to continue interrupted training.

  Epoch loop (Lines: 1194 – 1302)
    For each epoch:
      Phase transition (triggers at phase1_end, phase2_end):
        Switches training phase — updates which parameters are frozen
        and rebuilds the optimizer. Heavy augmentation is activated
        when Phase 3 begins.

      Training batches:
        MixUp/CutMix → forward (with AMP autocast) → loss →
        backward → gradient clipping → optimizer step →
        EMA update → LR scheduler step.
        Gradient accumulation runs for --accum-steps before stepping.
        NaN/Inf losses are detected and skipped.

      Validation (every --val-freq epochs):
        Uses EMA shadow model. Runs _sweep_threshold() to find the
        best F1 and threshold. Prints F1, Precision, Recall, AUC.

      Checkpoint saving:
        Saves when val F1 improves. Runs BN recalibration before save.
        Checkpoint contains: state_dict, epoch, best_val_f1,
        best_threshold, ema_state.

      Early stopping:
        Stops if no improvement for --early-stop consecutive epochs.

      SWA update:
        Calls swa_model.update_parameters(model) each epoch after
        --swa-start. Uses SWALR scheduler.

19. PREPROCESS.PY — RIM CROP PREPROCESSING
================================================================================
File: preprocess.py

Purpose:
  Runs ONCE before training. Crops each raw image to focus on the rim,
  discarding irrelevant background. Saves cropped images to a cache
  directory so training doesn't re-crop images on every epoch.

  extract_rim_crop(img_bgr, size, wide_scale=1.3) | Lines: 17 – 58
    1. Takes one channel from the BGR image (all channels are identical
       for grayscale-on-disk images).
    2. Applies Gaussian blur to reduce noise before circle detection.
    3. Runs cv2.HoughCircles to find the rim circle.
    4. If a circle is found:
         Computes the rim width estimate (18% of radius).
         Adds a margin (wide_scale × (rim_width + 10)).
         Crops the bounding box around the circle.
    5. If no circle is found: uses the full image (fallback).
    6. Resizes the crop to (size × size).

  process_single_image(task_info) | Lines: 61 – 77
    Worker function called in parallel by ProcessPoolExecutor.
    Skips already-processed images (idempotent restart support).
    Returns a status string: "success", "fallback", "skipped", "failed".

  main() | Lines: 80 – 165
    - Validates paths, reads CSV.
    - Peeks at a sample image to confirm grayscale format.
    - Builds task list of (src_path, dest_path, img_size) tuples.
    - Runs workers in parallel using ProcessPoolExecutor.
    - Prints a summary: rim found / no rim / skipped / failed counts.

  CLI arguments:
    --dataset   : folder of raw training images
    --csv       : train.csv with image_id column
    --cache-dir : where to write cropped images
    --img-size  : target crop size (default 300)
    --workers   : number of parallel CPU workers (default: auto)
